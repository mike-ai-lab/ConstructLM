# Git Hooks Setup - Prevent API Key Leaks

## Automatic Setup

Run this command to set up a pre-commit hook that checks for API keys:

```bash
# Windows (PowerShell)
echo "#!/bin/sh`nnode scripts/check-api-keys.js" > .git/hooks/pre-commit
```

```bash
# Linux/Mac
echo '#!/bin/sh\nnode scripts/check-api-keys.js' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

## Manual Check

You can also run the security check manually before committing:

```bash
node scripts/check-api-keys.js
```

## What It Does

The pre-commit hook will:
1. Scan all source files for API key patterns
2. Block commits if API keys are found
3. Provide recommendations for secure storage

## API Key Security Best Practices

### ✅ DO:
- Store API keys in `.env.local` (already in .gitignore)
- Use environment variables: `import.meta.env.VITE_GEMINI_API_KEY`
- Use header-based authentication: `headers: { 'x-goog-api-key': apiKey }`
- Keep API keys in localStorage (client-side only)

### ❌ DON'T:
- Hardcode API keys in source files
- Pass API keys as URL query parameters (visible in browser logs)
- Commit `.env.local` or any file containing real API keys
- Log API keys to console (use masking utilities)

## Security Utilities

Use the security utilities in `utils/securityUtils.ts`:

```typescript
import { safeLog, safeError, maskApiKeyInUrl } from '@/utils/securityUtils';

// Safe logging (automatically masks API keys)
safeLog('Making request to:', url);

// Mask API keys in URLs
const safeUrl = maskApiKeyInUrl(url);
console.log('URL:', safeUrl);
```

## If You Accidentally Commit an API Key

1. **Immediately revoke the exposed API key** in your provider's console
2. Generate a new API key
3. Update your `.env.local` with the new key
4. Remove the key from git history:
   ```bash
   git filter-branch --force --index-filter \
     "git rm --cached --ignore-unmatch <file-with-key>" \
     --prune-empty --tag-name-filter cat -- --all
   ```
5. Force push (⚠️ coordinate with team first):
   ```bash
   git push origin --force --all
   ```
